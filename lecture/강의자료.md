# Week 7. 최신 import(`import` 블록 + generate-config) & GitHub Actions OIDC

### [개념] 오늘의 목표 & 핵심 순간 ⭐
(1) Week6의 수작업 반복을 줄이는 **최신 import**: `import` 블록 + `terraform plan -generate-config-out`이 **HCL을 자동으로 생성**합니다. (2) CI에서 장기 AccessKey를 저장하는 대신 **OIDC**로 임시 자격증명을 받습니다. 여기서는 **왜 장기 키가 위험한지**를 이해하는 것이 핵심입니다.

### [실습] 2. ⭐ `import` 블록 작성 (명령어 대신 코드로)
`week7/import.tf`:
```hcl
import {
  to = aws_s3_bucket.w7
  id = "boaz26-w7-import-kdh1834"
}
```
`week7/main.tf`(provider만):
```hcl
terraform {
  required_version = ">= 1.9"
  required_providers { aws = { source = "hashicorp/aws", version = "~> 6.0" } }
}
provider "aws" { region = "ap-northeast-2" }
```

### [실습] 3. ⭐ config 자동 생성
```bash
cd week7 && terraform init
terraform plan -generate-config-out=generated.tf
```

`generated.tf`가 생성되고, 그 안에 `resource "aws_s3_bucket" "w7" { ... }` 가 실제 속성으로 **자동으로 입력되어** 있습니다. (Week6에서 반복하던 수작업이 사라집니다 ⭐)

### [함정] generate-config 주의
- 생성된 `generated.tf`는 **초안**. 리뷰 후 `import` 블록은 apply 뒤 지워도 됨(1회성).
- data source나 이미 관리 중인 리소스가 있으면 생성되지 않습니다.

### [개념] ⭐ 왜 OIDC인가 (장기 키 vs 임시 자격증명)
CI(GitHub Actions)에서 AWS를 사용하려면 자격증명이 필요합니다.
- **장기 AccessKey를 Secret에 저장** : 유출되면 무기한 악용될 수 있고, 순환(rotation)을 관리해야 하며, "누가 사용했는지" 추적하기 어렵습니다.
- **OIDC**: GitHub이 워크플로 실행마다 서명된 **단기 토큰**을 발급 → AWS가 이를 신뢰하여 **몇 분짜리 임시 자격증명**을 부여합니다. 따라서 저장해 둘 비밀키가 **없습니다**.
```
 [GitHub Actions] --OIDC 토큰--> [AWS IAM OIDC Provider]
                                        │ AssumeRoleWithWebIdentity
                                        ▼
                                 임시 자격(15분~1시간)
```

### [실습] 5. AWS 측: OIDC provider + Role (콘솔/CLI 택1, 개념 확인용)
IAM → Identity providers → Add provider → **OpenID Connect**
- Provider URL: `https://token.actions.githubusercontent.com`
- Audience: `sts.amazonaws.com`

그다음 Role을 생성하고 신뢰 정책(trust policy)을 지정합니다.
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Federated": "arn:aws:iam::<ACCOUNT_ID>:oidc-provider/token.actions.githubusercontent.com" },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": { "token.actions.githubusercontent.com:aud": "sts.amazonaws.com" },
      "StringLike": { "token.actions.githubusercontent.com:sub": "repo:<ORG>/<REPO>:ref:refs/heads/main" }
    }
  }]
}
```

### [실습] 6. GitHub Actions 워크플로 (키 없음)
`.github/workflows/terraform.yml`:
```yaml
name: terraform-plan
on: [push]
permissions:
  id-token: write      # OIDC 토큰 발급에 필수 ⭐
  contents: read
jobs:
  plan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::<ACCOUNT_ID>:role/boaz-gha-oidc
          aws-region: ap-northeast-2
      - uses: hashicorp/setup-terraform@v3
      - run: terraform init
      - run: terraform plan
```

### [확인] OIDC 동작
Actions 로그에서 `configure-aws-credentials`가 `AssumeRoleWithWebIdentity`로 임시 자격증명을 획득 → `terraform plan` 성공. **어디에도 AccessKey를 저장하지 않았습니다.**
